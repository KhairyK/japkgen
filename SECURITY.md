# Security Policy

## Supported Versions

The following table outlines which versions of this project are currently receiving security updates and maintenance support.

| Version | Supported |
| ------- | --------- |
| 2.0.0   | ☑️        |
| 1.2.0   | ☑️        |
| 1.1.0   | ⚠️        |
| 1.0.0   | ✖️        |

Versions that are no longer supported will not receive security patches, vulnerability fixes, or maintenance updates. Users are strongly encouraged to upgrade to a supported version.

---

## Reporting a Vulnerability

We take the security of this project seriously and appreciate responsible disclosure from security researchers, contributors, and users.

If you believe you have discovered a security vulnerability, please report it privately and responsibly.

### Preferred Reporting Methods

Please use one of the following channels:

- GitHub Security Advisories
- Security Email: opendnf.security@gmail.com

Do **NOT** report security vulnerabilities through:

- Public GitHub Issues
- Discussions
- Pull Requests
- Social Media Platforms

Public disclosure before remediation may put users at risk and could delay the resolution process.

---

## Required Information

To help us investigate and resolve issues efficiently, please include as much of the following information as possible:

- Detailed description of the vulnerability
- Steps to reproduce the issue
- Affected versions and environments
- Potential impact and attack scenario
- Proof-of-concept code or screenshots (if applicable)
- Suggested mitigation or fix (optional)

Incomplete reports may require additional follow-up before validation can begin.

---

## Response Process

After receiving a report, our security team will:

1. Acknowledge receipt of the report
2. Perform an initial assessment and validation
3. Determine severity and affected components
4. Develop and test remediation measures
5. Coordinate responsible disclosure when appropriate

### Expected Timeline

| Stage                       | Estimated Time                   |
| --------------------------- | -------------------------------- |
| Initial Response            | Within 48 hours                  |
| Validation & Assessment     | Within 7 business days           |
| Remediation & Patch Release | Based on severity and complexity |

Please note that complex vulnerabilities may require additional investigation time.

---

## Disclosure Policy

We follow a responsible disclosure process.

Reporters are expected to:

- Avoid exploiting vulnerabilities beyond what is necessary for validation
- Avoid accessing, modifying, or deleting data belonging to others
- Avoid actions that may negatively affect service availability or integrity
- Refrain from public disclosure until an official fix or advisory has been released

Once the issue has been resolved, we may publicly acknowledge the reporter unless anonymity is requested.

---

## Security Updates

Security-related updates and advisories may be published through:

- GitHub Releases

- GitHub Security Advisories

Users are encouraged to regularly update to the latest supported release to ensure maximum security and stability.
